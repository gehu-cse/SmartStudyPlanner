Copy constructor: ClassName(const ClassName &obj), creates a new object from an existing one; the argument must be passed by reference (by value would recurse infinitely).
NOTE|CLASS_OBJ|Copy constructor is called when: (1) an object is initialised from another (Box b4 = b3;), (2) an object is passed by value to a function, (3) an object is returned by value.
NOTE|CLASS_OBJ|Shallow copy vs deep copy: the compiler's default copy constructor copies pointer values only (shallow), so two objects point to the same memory and both destructors free it (double free). A user-defined copy constructor that allocates new memory and copies content is a deep copy.
NOTE|CLASS_OBJ|Constructor overloading: several constructors with different parameters. Initializer list : l(x), b(y) initialises members before body runs; required for const and reference members.
NOTE|CLASS_OBJ|Dynamic initialisation: values supplied at run time (Box b(a, c); with variables).

TOPIC|EXCEPT
NOTE|EXCEPT|An exception is a run-time error (divide by zero, array out of bounds, file not found, memory not available). C++ separates normal code from error handling using three keywords: try (block that may cause exception), throw (raises exception, any type), catch (handler, selected by type).
NOTE|EXCEPT|double divide(int a, int b){ if(b == 0) throw "Division by zero"; return (double)a / b; } int main(){ try { cout << divide(10, 0); } catch (const char *msg) { cout << "Error: " << msg; } catch (int e) { cout << "int exception"; } catch (...) { cout << "any other exception"; } // catch-all }
NOTE|EXCEPT|Control jumps from throw to the first matching catch; code after throw in try is skipped; if no handler matches, terminate() ends the program. Several catch blocks can follow one try; catch(...) must be last.
NOTE|EXCEPT|Re-throwing: inside a catch block, throw; passes the same exception to the outer handler. Nested try blocks are allowed. Functions may specify exceptions (old style throw(int)). Standard exceptions in <exception>: bad_alloc, out_of_range, invalid_argument, exception::what().
NOTE|EXCEPT|try { try { throw 5; } catch(int x){ cout << "inner "; throw; } } // rethrow catch(int x){ cout << "outer " << x; } // inner outer 5

TOPIC|INHERIT
NOTE|INHERIT|Inheritance lets a new class (derived / child / sub class) reuse and extend the members of an existing class (base / parent / super class). It models the 'is-a' relationship (a Car is a Vehicle). Advantages: code reuse, less development time, easy extension, supports polymorphism, hierarchical classification. Syntax: class Derived : access_specifier Base { ... };
NOTE|INHERIT|Type Structure Example Single A -> B class B : public A Multiple A, B -> C class C : public A, public B Multilevel A -> B -> C class C : public B (B : public A) Hierarchical A -> B, A -> C class B : public A; class C : public A Hybrid combination (e.g. hierarchical + multiple) needs virtual base class to avoid ambiguity class Person { protected: string name; int age; public: void getP(){ cin >> name >> age; } }; class Employee : public Person { float sal; public: void getE(){ getP(); cin >> sal; } // single inheritance void show(){ cout << name <<...
NOTE|INHERIT|Base class member public inheritance protected inheritance private inheritance public public protected private protected protected protected private private not inherited (inaccessible) not inherited not inherited
NOTE|INHERIT|Private members of base are present in the derived object but not directly accessible; use public/protected base functions. protected exists to give derived classes access while hiding from outside. Default inheritance mode for class is private, for struct is public.
NOTE|INHERIT|Public inheritance keeps the is-a relation (most common). Private/protected inheritance hide the base interface from users of the derived class.
NOTE|INHERIT|Order of construction: base class constructor first, then derived class constructor. For multiple inheritance, base constructors run in the order of their declaration in the derived class header. Destruction is in the reverse order (derived destructor first, then base).
NOTE|INHERIT|Passing parameters to base class constructor: use the initializer list of the derived constructor: Derived(int a, int b) : Base(a) { ... }. If the base has a default constructor it is called automatically; if the base has only parameterised constructors the derived must call one explicitly.
NOTE|INHERIT|class A { public: A(int x){ cout << "A(" << x << ") "; } ~A(){ cout << "~A "; } }; class B { public: B(){ cout << "B "; } ~B(){ cout << "~B "; } }; class C : public A, public B { public: C(int x, int y) : A(x) { cout << "C(" << y << ") "; } ~C(){ cout << "~C "; } }; int main(){ C c(1, 2); } // output: A(1) B C(2) ~C ~B ~A
NOTE|INHERIT|In multiple inheritance, if both bases have a member with the same name, the call obj.f() is ambiguous; resolve with obj.A::f();. In hybrid inheritance (diamond): B and C inherit from A, and D inherits from B and C. D then contains two copies of A's members, so d.x is ambiguous and memory is wasted. Declaring the common base as virtual makes only one shared copy of A.
NOTE|INHERIT|class A { public: int x; A(){ x = 10; } }; class B : virtual public A { }; class C : virtual public A { }; class D : public B, public C { }; // A int main(){ D d; cout << d.x; } // / \ one copy of A, no ambiguity -> 10 // B C // \ / // D
NOTE|INHERIT|With a virtual base class, the constructor of the virtual base is called first, and by the most derived class (D), not by B or C.
NOTE|INHERIT|Other points: constructors/destructors/assignment operator/friends are not inherited. A derived class can override (redefine) a base function; the base version is hidden (use Base::f() to call it). Composition ('has-a') is an alternative to inheritance (an object as a member of another).

TOPIC|OOP_BASICS
NOTE|OOP_BASICS|Early programs were written in the procedural style (C, Pascal, FORTRAN): a program is a list of instructions grouped into functions, and data is kept in global or shared variables. As programs grow, this style creates problems: any function can change global data, so a bug in one place breaks others; code is hard to reuse; and the program does not model real-world things naturally. OOP solves these by putting data and the functions that work on it into one unit (object) and by controlling who can touch the data.
NOTE|OOP_BASICS|Security: data hiding stops accidental or unauthorised change.
NOTE|OOP_BASICS|Reusability: inheritance and templates let existing code be reused instead of rewritten.
NOTE|OOP_BASICS|Maintainability: change inside a class does not affect other parts if the interface is the same.
NOTE|OOP_BASICS|Real-world modelling: objects such as Student, Account, Car map directly to program entities.
NOTE|OOP_BASICS|Extensibility: new features are added by creating new classes, not editing old ones.
NOTE|OOP_BASICS|Basis POP OOP Main idea Program = functions + data Program = objects that communicate Design approach Top-down Bottom-up Data Global data shared by all functions, little protection Data hidden inside object, accessed through member functions Importance Functions (what to do) Data (who does it) Reuse Copy and modify functions Inheritance, composition, templates Overloading Not supported Function and operator overloading Real-world modelling Difficult Easy Access control No access specifiers private, protected, public Examples C, Pascal, COBOL C++,...
NOTE|OOP_BASICS|Object: a run-time entity with state (data members), behaviour (member functions) and identity. Example: a Student object with roll, name and function display().
NOTE|OOP_BASICS|Class: a user-defined data type that is the blueprint of objects. It describes members but occupies no memory until an object is created.
NOTE|OOP_BASICS|Encapsulation: wrapping data and functions into a single unit (the class). It is the mechanism that supports data hiding.
NOTE|OOP_BASICS|Data hiding: keeping data members private so they can be accessed only through public member functions.
NOTE|OOP_BASICS|Abstraction: showing only essential features and hiding implementation details. We use cout without knowing how it works inside. In C++ abstraction is achieved with classes and access specifiers (and abstract classes).
NOTE|OOP_BASICS|Inheritance: process by which one class (derived) acquires properties of another (base). Supports reuse and hierarchical classification.
NOTE|OOP_BASICS|Polymorphism: 'many forms': the same function name or operator behaves differently in different contexts (overloading, overriding, virtual functions).
NOTE|OOP_BASICS|Dynamic binding: the code executed for a call is decided at run time (virtual functions).
NOTE|OOP_BASICS|Message passing: objects communicate by calling each other's member functions, e.g. s1.display();.
NOTE|OOP_BASICS|Developed by Bjarne Stroustrup at AT&T Bell Labs, started in 1979 as 'C with Classes', renamed C++ in 1983. Standardised by ISO (C++98, C++11, C++14, C++17, C++20).
NOTE|OOP_BASICS|C++ is a superset of C (almost all C code works), supports procedural, object-oriented and generic programming, and gives low-level control with high-level features.
NOTE|OOP_BASICS|Features: classes and objects, inheritance, polymorphism, templates, exceptions, namespaces, references, STL, operator overloading, inline functions, default arguments.

NOTE|OPOVL|Q. Why is the copy constructor argument a reference?
NOTE|OPOVL|A. If passed by value, making the copy would call the copy constructor again, causing infinite recursion. A reference avoids the copy.

NOTE|OPOVL|A. A member function belongs to the class, is called through an object and has this. A friend function is outside the class, called like a normal function with objects as arguments, but can access private members.

NOTE|VIRTUAL|Polymorphism means 'many forms': one interface, many implementations. C++ supports two kinds.
NOTE|VIRTUAL|Compile-time (static) polymorphism Run-time (dynamic) polymorphism Function overloading, operator overloading, templates Function overriding with virtual functions Early binding: call linked at compile time Late binding: call decided at run time by object type Faster, less flexible Slight overhead (vtable lookup), very flexible Function overloading Function overriding Same name, different parameters Same name AND same signature Same class (or same scope) Base class and derived class Resolved at compile time Resolved at run time if base function is...
NOTE|VIRTUAL|A virtual function is a base class member function declared with virtual, expected to be overridden. When called through a base class pointer or reference, the version of the object actually pointed to runs (late binding). Without virtual, the pointer type decides (early binding).
NOTE|VIRTUAL|Rules: must be a member function; cannot be static; can be friend of another class; accessed through pointer/reference to get run-time effect; prototype must match in derived class; if not overridden, base version is used; constructors cannot be virtual but destructors can.
NOTE|VIRTUAL|Implementation: every class with virtual functions has a vtable (table of function addresses). Each object stores a hidden vptr pointing to its class's vtable. A virtual call goes ptr -> vptr -> vtable -> function.
NOTE|VIRTUAL|class Base { public: void show() { cout << "Base show\n"; } // non-virtual virtual void print(){ cout << "Base print\n"; } }; // virtual class Derived : public Base { public: void show() { cout << "Derived show\n"; } void print() { cout << "Derived print\n"; } }; int main(){ Base *p; Derived d; p = &d; p->show(); // Base show (early binding, pointer type) p->print(); // Derived print (late binding, object type) }
NOTE|VIRTUAL|Pure virtual function: virtual void area() = 0; has no definition in base. A class having at least one pure virtual function is an abstract class: objects cannot be created, but pointers and references to it can.
NOTE|VIRTUAL|Any derived class must override all pure virtual functions, otherwise it is also abstract.
NOTE|VIRTUAL|Abstract classes define an interface/contract for derived classes (e.g. Shape with area(); Circle, Rectangle implement).
NOTE|VIRTUAL|class Shape { public: virtual float area() = 0; virtual ~Shape() {} }; class Circle : public Shape { float r; public: Circle(float x):r(x){} float area(){ return 3.14f*r*r; } }; class Rect : public Shape { float l,b; public: Rect(float x,float y):l(x),b(y){} float area(){ return l*b; } }; int main(){ Shape *s[2] = { new Circle(2), new Rect(3,4) }; for(int i = 0; i < 2; i++){ cout << s[i]->area() << endl; delete s[i]; } } // 12.56 12
NOTE|VIRTUAL|If a derived object is deleted through a base pointer and the base destructor is not virtual, only the base destructor runs and the derived part is not cleaned (memory leak, undefined behaviour). Make the base destructor virtual so destructors run derived first, then base.
NOTE|VIRTUAL|class B { public: virtual ~B(){ cout << "~B "; } }; class D : public B { public: ~D(){ cout << "~D "; } }; int main(){ B *p = new D; delete p; } // with virtual: ~D ~B without: ~B only
