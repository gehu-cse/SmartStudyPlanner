TOPIC|AVL
NOTE|AVL|An AVL tree (Adelson-Velsky and Landis) is a height-balanced BST: for every node, balance factor = height(left) - height(right) is -1, 0 or +1. Because height is always O(log n), search, insert and delete are guaranteed O(log n). After insertion or deletion, if a node becomes unbalanced, restore balance by rotations.
NOTE|AVL|Case Cause (insertion) Fix LL new node in left subtree of left child single right rotation at unbalanced node RR new node in right subtree of right child single left rotation LR new node in right subtree of left child left rotation on left child, then right rotation on node RL new node in left subtree of right child right rotation on right child, then left rotation on node Example: Insert 30, 20, 10 30 -> left 20 -> left 10 gives LL imbalance at 30 (BF = +2). Right rotation makes 20 the root with children 10 and 30.
NOTE|AVL|Example: Insert 10, 30, 20 10 -> right 30 -> left 20 gives RL imbalance at 10. Right rotate 30 (20 becomes parent of 30), then left rotate 10: root 20, children 10 and 30.
NOTE|AVL|Rotations are O(1); at most one rotation (single or double) is needed after an insertion. Minimum nodes in AVL tree of height h: N(h) = N(h-1) + N(h-2) + 1.
NOTE|AVL|Exam tip: Unit 3 exam favourites: tree properties (n0 = n2 + 1); traversals of given tree; tree from inorder + preorder; BST insertion and deletion; AVL rotations with insertion sequence; heap insert/delete and heap sort; Huffman tree and codes; threaded tree; extended binary tree.
NOTE|AVL|Q. Maximum nodes in a binary tree of height 4 (root at level 1)?
NOTE|AVL|A. Its height is at most about 1.44 log n because balance factors stay within -1 to +1.

TOPIC|BTREE
NOTE|BTREE|A B-tree of order m is a balanced multiway search tree designed for disks, where one node = one disk block.
NOTE|BTREE|Every node has at most m children and m - 1 keys. Every non-root internal node has at least ceil(m/2) children (ceil(m/2) - 1 keys). The root has at least 2 children (if not a leaf). All leaves are at the same level.
NOTE|BTREE|Keys in a node are sorted; keys in child i lie between key i-1 and key i.
NOTE|BTREE|Search: like BST but multiway; O(log n) block accesses. Insertion: insert in the leaf; if the node overflows (more than m-1 keys) split it around the median and push the median up to the parent (may propagate to the root, increasing height). Deletion: remove key; if a node underflows, borrow from a sibling or merge with it.
NOTE|BTREE|Tree grows upwards (height only increases when the root splits), so it stays balanced.
NOTE|BTREE|Example: B-tree of order 3 (2-3 tree), insert 10, 20, 30 Insert 10, 20 in one node. Inserting 30 overflows (3 keys > 2): split around median 20; 20 moves up as new root with children [10] and [30].
NOTE|BTREE|B+ tree: a variant where all data records (or record pointers) are stored only in leaf nodes, and internal nodes hold only keys as index. Leaves are linked in a list, so range queries and sequential scans are fast. Keys may be repeated in internal nodes. Internal nodes hold more keys (no data pointers), so tree is shallower.
NOTE|BTREE|B-tree B+ tree Data in internal and leaf nodes Data only in leaf nodes Leaves not linked Leaves linked for sequential access Search may end at internal node Search always reaches a leaf (uniform time) Better for single key lookup Better for range queries and full scans Used in some file systems Used in databases and file systems (NTFS, indexes)

TOPIC|FILE_ORG
NOTE|FILE_ORG|A file is a collection of records stored on secondary storage. Data is moved in blocks (pages). Blocking factor bfr = floor(block size / record size). Disk access time = seek + rotational latency + transfer; so organisation aims to minimise block accesses.
NOTE|FILE_ORG|Sequential file: records in key order; good for batch processing; search O(n)/binary search on blocks; insertion costly. Direct (hashed) file: record address computed by hash function; fast direct access. Indexed sequential (ISAM): sequential file plus an index. Heap (pile) file: unordered, appended at the end.
NOTE|FILE_ORG|An index is a separate structure holding (key, pointer to record/block) pairs, much smaller than the data file, so searching it is fast (like a book index).
NOTE|FILE_ORG|Primary index: on the ordering key of a sequentially ordered file; one entry per block (sparse). Clustering index: on a non-key ordering field. Secondary index: on a non-ordering field; dense (entry for every record).
NOTE|FILE_ORG|Multilevel index: index on the index, to reduce search to few block accesses; B-trees generalise this.
NOTE|FILE_ORG|Dense index: one entry per record. Sparse index: one entry per block.

TOPIC|GRAPH_TRAV
NOTE|GRAPH_TRAV|BFS (Breadth First Search): start at source, visit all neighbours, then their neighbours (level by level) using a queue and a visited array. Finds shortest path in unweighted graph. Time O(V + E) with adjacency list (O(V2) with matrix).
NOTE|GRAPH_TRAV|DFS (Depth First Search): go as deep as possible along a path, then backtrack, using a stack or recursion.
NOTE|GRAPH_TRAV|Time O(V + E). Applications: cycle detection, topological sort, connected components, solving mazes, finding strongly connected components.

TOPIC|HASH
NOTE|HASH|Hashing maps a key to a table index using a hash function h(k), giving average O(1) search, insert and delete. The table is the hash table of size m.
NOTE|HASH|Good hash function: easy to compute, spreads keys uniformly, minimises collisions. Methods: division h(k) = k mod m (choose m prime); mid-square (square key, take middle digits); folding (split key into parts and add); multiplication method; digit extraction.
NOTE|HASH|Collision: two keys give the same index. Load factor = n / m.
NOTE|HASH|Chaining (open hashing): each slot holds a linked list of all keys that hash there; table can hold more keys than slots; search time O(1 + load factor).
NOTE|HASH|Open addressing (closed hashing): all keys stored in table; on collision probe for another free slot. Linear probing: h(k, i) = (h(k) + i) mod m (primary clustering). Quadratic probing: (h(k) + c1 i + c2 i2) mod m (secondary clustering). Double hashing: (h1(k) + i h2(k)) mod m, fewest clusters. Deletion needs a tombstone marker.
NOTE|HASH|Example: Linear probing, m = 10, keys 25, 35, 15, 22 25 -> 5. 35 -> 5 taken -> 6. 15 -> 5, 6 taken -> 7. 22 -> 2. Table: index 2=22, 5=25, 6=35, 7=15.
NOTE|HASH|int table[10]; // -1 means empty void insertKey(int k){ int i = k % 10; while(table[i] != -1) i = (i + 1) % 10; // linear probing table[i] = k; } Exam tip: Unit 4 exam favourites: sorting comparison table; trace of bubble/insertion/quick/merge/heap on a sample array; quick sort worst case; binary search with trace; hashing methods and collision resolution with an example.

TOPIC|HEAP
NOTE|HEAP|A complete binary tree with the heap property. Max-heap: every parent >= its children (root is maximum).
NOTE|HEAP|Min-heap: every parent <= children (root is minimum). Stored in an array: children of i at 2i and 2i+1.
NOTE|HEAP|Insert: place at the next free position (end), then sift up (swap with parent while violating). O(log n). Delete root: replace root with the last element, reduce size, sift down (heapify, swap with larger child in max-heap).
NOTE|HEAP|O(log n). Build heap from array: heapify from n/2 down to 1, O(n).
NOTE|HEAP|Applications: priority queue, heap sort, k-th largest, scheduling.
NOTE|HEAP|Example: Max-heap insertion 10, 20, 15, 30, 40 Insert 10. Insert 20: sift up, root 20, child 10. Insert 15: right child of 20. Insert 30: under 10 (left of 10), sift up past 10 and 20 -> root 30. Insert 40: becomes root; array result 40, 30, 15, 10, 20.
NOTE|HEAP|void heapify(int a[], int n, int i){ // max-heap, 0-indexed int l = 2*i + 1, r = 2*i + 2, big = i; if(l < n && a[l] > a[big]) big = l; if(r < n && a[r] > a[big]) big = r; if(big != i){ int t = a[i]; a[i] = a[big]; a[big] = t; heapify(a, n, big); } }

TOPIC|HUFFMAN
NOTE|HUFFMAN|Huffman coding is a greedy lossless compression method that gives shorter prefix-free binary codes to more frequent characters. It builds a Huffman tree (a weighted extended binary tree with minimum weighted path length).
NOTE|HUFFMAN|1. Create a leaf node for each character with its frequency and put all in a min-priority queue.
NOTE|HUFFMAN|2. Remove the two nodes with smallest frequency; create a new internal node with frequency = their sum, with them as children.
NOTE|HUFFMAN|3. Insert the new node back. Repeat until only one node (root) remains.
NOTE|HUFFMAN|4. Assign 0 to left edges and 1 to right edges; the code of a character is the path from root to its leaf.
NOTE|HUFFMAN|Example: a:45, b:13, c:12, d:16, e:9, f:5 Merge f(5)+e(9)=14; c(12)+b(13)=25; 14+d(16)=30; 25+30=55; a(45)+55=100. Codes: a=0, c=100, b=101, f=1100, e=1101, d=111. Total bits = 45x1 + 12x3 + 13x3 + 5x4 + 9x4 + 16x3 = 224 vs 300 with 3-bit fixed codes.

TOPIC|MST
NOTE|MST|A spanning tree connects all V vertices using V - 1 edges with no cycle. The MST of a weighted connected undirected graph is the spanning tree of minimum total weight. Both algorithms below are greedy.
NOTE|MST|Kruskal's algorithm: sort all edges by weight; for each edge in order, add it if it does not form a cycle (check with Union-Find); stop when V - 1 edges are chosen. Time O(E log E) (sorting). Good for sparse graphs.
NOTE|MST|Prim's algorithm: start from any vertex; repeatedly add the minimum-weight edge connecting the tree to a vertex outside it. Time O(V2) with matrix, O(E log V) with heap. Good for dense graphs.
NOTE|MST|Example: Edges: A-B 4, A-C 3, B-C 1, B-D 2, C-D 4, D-E 2, C-E 6 Kruskal sorted: B-C 1, B-D 2, D-E 2, A-C 3, A-B 4, C-D 4, C-E 6. Take B-C, B-D, D-E, A-C (4 edges for 5 vertices). Total = 1+2+2+3 = 8.

TOPIC|QUEUE
NOTE|QUEUE|A queue is a linear structure where insertion is at the rear and deletion at the front: FIFO (First In First Out), like a ticket line. Operations: enqueue, dequeue, front, isEmpty, isFull. Applications: CPU scheduling, printer spooling, BFS, buffers, call centres.
NOTE|QUEUE|#define MAX 5 int q[MAX], front = -1, rear = -1; void enqueue(int x){ if(rear == MAX - 1){ printf("Overflow"); return; } if(front == -1) front = 0; q[++rear] = x; } int dequeue(){ if(front == -1 // front > rear){ printf("Underflow"); return -1; } return q[front++]; }
NOTE|QUEUE|Drawback of linear queue: after dequeues the freed front cells cannot be reused, so overflow occurs even when the queue has empty space.
NOTE|QUEUE|Treat the array as a circle: after the last index comes index 0. Rear moves as rear = (rear + 1) % MAX, front as front = (front + 1) % MAX. Full when (rear + 1) % MAX == front; empty when front == -1. Uses space fully.
NOTE|QUEUE|void enq(int x){ if((rear + 1) % MAX == front){ printf("Full"); return; } if(front == -1) front = rear = 0; else rear = (rear + 1) % MAX; q[rear] = x; } int deq(){ if(front == -1){ printf("Empty"); return -1; } int x = q[front]; if(front == rear) front = rear = -1; else front = (front + 1) % MAX; return x; }
NOTE|QUEUE|Deque (double-ended queue): insertion and deletion at both ends. Input-restricted: insert only at rear, delete at both. Output-restricted: delete only at front, insert at both. Can act as both stack and queue.
NOTE|QUEUE|Priority queue: every element has a priority; the element with highest priority is removed first; equal priorities follow FIFO. Implementations: unsorted array/list (insert O(1), delete O(n)), sorted list (insert O(n), delete O(1)), binary heap (both O(log n)). Applications: OS scheduling, Dijkstra, Huffman coding.

TOPIC|SORTING
NOTE|SORTING|Linear (sequential) search: compare the key with each element in turn. Works on unsorted data. Best O(1), average and worst O(n).
NOTE|SORTING|Binary search: array must be sorted. Compare key with middle; if equal done; if smaller search left half, else right half. Each step halves the range: worst/average O(log n), best O(1). Needs random access (array), not suited to linked lists.
NOTE|SORTING|int linear(int a[], int n, int k){ for(int i = 0; i < n; i++) if(a[i] == k) return i; return -1; } int binary(int a[], int n, int k){ int low = 0, high = n - 1; while(low <= high){ int mid = (low + high) / 2; if(a[mid] == k) return mid; else if(k < a[mid]) high = mid - 1; else low = mid + 1; } return -1; } Example: Binary search for 23 in 2, 5, 8, 12, 16, 23, 38, 56 low=0, high=7, mid=3 (12) < 23 so low=4. mid=5 (23) found at index 5 in 2 comparisons.

NOTE|SORTING|Sorting arranges data in ascending/descending order. Internal sort: data fits in memory (bubble, insertion, quick, merge, heap). External sort: data on disk (external merge sort).
NOTE|SORTING|Stable: equal keys keep original relative order. In-place: uses O(1) extra memory. Adaptive: faster on nearly sorted input. Comparison-based sorts need at least O(n log n) comparisons in worst case.
NOTE|SORTING|Bubble sort: repeatedly compare adjacent elements and swap if out of order; after pass i the i-th largest is at its place. n-1 passes. With a swapped flag the best case (sorted) is O(n). Best O(n), average and worst O(n2), stable, in-place.
NOTE|SORTING|void bubble(int a[], int n){ for(int i = 0; i < n - 1; i++){ int sw = 0; for(int j = 0; j < n - 1 - i; j++) if(a[j] > a[j+1]){ int t = a[j]; a[j] = a[j+1]; a[j+1] = t; sw = 1; } if(!sw) break; } } Example: Bubble sort 5 3 8 1 Pass 1: 3 5 1 8. Pass 2: 3 1 5 8. Pass 3: 1 3 5 8 sorted.
NOTE|SORTING|Insertion sort: take each element and insert it at the correct position in the already sorted left part by shifting larger elements right. Best O(n) (sorted), average/worst O(n2), stable, in-place, good for small or nearly sorted data and online sorting.
NOTE|SORTING|void insertion(int a[], int n){ for(int i = 1; i < n; i++){ int key = a[i], j = i - 1; while(j >= 0 && a[j] > key){ a[j+1] = a[j]; j--; } a[j+1] = key; } }
NOTE|SORTING|Divide and conquer: choose a pivot, partition so elements smaller than pivot go left and larger go right (pivot lands in its final place), then sort both parts recursively. Average O(n log n); worst O(n2) when pivot is always smallest/largest (e.g. already sorted input with first/last pivot); space O(log n) stack; not stable, in-place. Random or median-of-three pivot avoids the worst case.
NOTE|SORTING|int partition(int a[], int lo, int hi){ int pivot = a[hi], i = lo - 1; for(int j = lo; j < hi; j++) if(a[j] <= pivot){ i++; int t = a[i]; a[i] = a[j]; a[j] = t; } int t = a[i+1]; a[i+1] = a[hi]; a[hi] = t; return i + 1; } void quick(int a[], int lo, int hi){ if(lo < hi){ int p = partition(a, lo, hi); quick(a, lo, p-1); quick(a, p+1, hi); } } Example: Quick sort 10 80 30 90 40 50 70 (pivot = last = 70) After partition: 10 30 40 50 70 90 80 -> pivot 70 in place at index 4; sort left (10 30 40 50) and right (90 80) recursively.
NOTE|SORTING|Divide and conquer: split array into two halves, sort each recursively, merge two sorted halves into one using a temporary array. Always O(n log n) (best, average, worst), needs O(n) extra space, stable. Two-way merge uses two sorted lists; good for linked lists and external sorting.
NOTE|SORTING|void merge(int a[], int l, int m, int r){ int t[100], i = l, j = m + 1, k = 0; while(i <= m && j <= r) t[k++] = (a[i] <= a[j]) ? a[i++] : a[j++]; while(i <= m) t[k++] = a[i++]; while(j <= r) t[k++] = a[j++]; for(i = 0; i < k; i++) a[l + i] = t[i]; } void msort(int a[], int l, int r){ if(l < r){ int m = (l + r) / 2; msort(a, l, m); msort(a, m+1, r); merge(a, l, m, r); } } Recurrence: T(n) = 2T(n/2) + O(n) which gives O(n log n).
NOTE|SORTING|Build a max-heap from the array (O(n)); then repeatedly swap the root (largest) with the last element of the heap, reduce heap size by one and heapify the root (O(log n)). Total O(n log n) in all cases, in-place O(1) space, not stable.
NOTE|SORTING|void heapsort(int a[], int n){ for(int i = n/2 - 1; i >= 0; i--) heapify(a, n, i); // build max-heap for(int i = n - 1; i > 0; i--){ int t = a[0]; a[0] = a[i]; a[i] = t; heapify(a, i, 0); } }

NOTE|STACK|A stack is a linear structure in which insertion and deletion happen only at one end, the top. It follows LIFO (Last In First Out), like a pile of plates.
NOTE|STACK|Operations: push (insert at top), pop (remove top), peek/top (read top), isEmpty, isFull. Overflow: push on full stack. Underflow: pop on empty stack. All operations O(1).
NOTE|STACK|#define MAX 100 int s[MAX], top = -1; void push(int x){ if(top == MAX - 1) printf("Overflow\n"); else s[++top] = x; } int pop(){ if(top == -1){ printf("Underflow\n"); return -1; } return s[top--]; } int peek(){ return top == -1 ? -1 : s[top]; }
NOTE|STACK|Applications: expression conversion and evaluation, function call management (call stack), recursion, parenthesis matching, undo/redo, backtracking, DFS, reversing a string.

NOTE|TREE_BST|Binary tree: each node has at most two children (left, right). Strict (full): each node has 0 or 2 children.
NOTE|TREE_BST|Complete: all levels filled except possibly the last, which is filled left to right. Perfect: all leaves at same level, all internal nodes have 2 children. Skewed: all nodes only left or only right.
NOTE|TREE_BST|Properties (root at level 1): max nodes at level i = 2i-1. Max nodes in tree of height h = 2h - 1. Minimum height with n nodes = ceil(log2(n+1)). For any non-empty binary tree: n0 = n2 + 1 (leaves = nodes with two children + 1). Total nodes = n0 + n1 + n2; edges = n - 1.
NOTE|TREE_BST|Array representation (index from 1): root at 1, left child of i at 2i, right child at 2i+1, parent at floor(i/2). Good for complete trees (no waste), poor for skewed. Linked representation: node {left, data, right}, 2n - (n-1) = n + 1 NULL pointers.

NOTE|TREE_BST|Construction: inorder + preorder (or inorder + postorder) gives a unique tree: the first preorder (last postorder) element is root; elements left of root in inorder form left subtree, right ones form right subtree; recurse. Preorder + postorder alone is not enough.
NOTE|TREE_BST|Expression tree: leaves are operands, internal nodes operators. Inorder gives infix, preorder prefix, postorder postfix.
NOTE|TREE_BST|Non-recursive inorder uses a stack: go left pushing nodes; pop, visit, go right.
NOTE|TREE_BST|In a binary tree with n nodes, n + 1 pointers are NULL. A threaded binary tree uses these NULL pointers to store threads: a NULL right pointer points to the inorder successor, a NULL left pointer to the inorder predecessor.
NOTE|TREE_BST|A flag bit tells whether a pointer is a child link or thread. Types: single-threaded (right only) and double-threaded.
NOTE|TREE_BST|Advantage: inorder traversal without recursion or stack, faster, saves space.
NOTE|TREE_BST|Replace every NULL pointer of a binary tree by a special external node. Every internal node then has exactly 2 children. If I = internal path length, E = external path length, n = internal nodes: E = I + 2n. Useful for Huffman coding and analysing search trees.
NOTE|TREE_BST|For every node: all keys in left subtree < node < all keys in right subtree. Inorder traversal gives sorted order. Search, insert, delete take O(h): O(log n) for balanced tree, O(n) for skewed tree.
NOTE|TREE_BST|Search: compare with root; go left if smaller, right if larger. Insert: search for the key's place and attach as a new leaf (inserting 50, 30, 70, 20, 40 builds root 50 with children 30 and 70; 20, 40 under 30).
NOTE|TREE_BST|Delete cases: (1) leaf: remove it. (2) one child: replace node with its child. (3) two children: replace with inorder successor (minimum of right subtree) or inorder predecessor, then delete that node.
NOTE|TREE_BST|Path length: internal path length is the sum of levels of all nodes; average search cost is path length / n. A smaller path length means a better (more balanced) tree.
